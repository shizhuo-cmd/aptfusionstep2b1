# CADETS 大根节点审计与正常样本阈值校准实验（2026-08-01）

## 结论先行

- CADETS 的超大任务图确实主要由采集侧汇聚根导致：这些根没有父进程、开始时间为 `0`，却直接派生数万子进程，根自身几乎只有派生记录。
- 这不是适合直接按固定时间间隔切开的普通长任务。已完成的时间硬切对照会把少数根切成数百片，降低 CADETS 的检测指标；因此不作为默认方案。
- 当前更直接、在两个数据集都有效的改进是把正常样本阈值的目标误报率从 `1%` 调整为预先固定的 `2%`。该改变只用时间上独立的正常任务图选阈值，不使用攻击图标签调参。

## 大根节点定点审计

审计对象是 CADETS 基线中节点数最多的 8 张任务图。为避免重新解析全部原始日志，只对包含这些根 UUID 的记录做一次定点扫描。

这些根不具备一个真实系统任务的行为边界，更像审计采集或初始化阶段的汇聚节点。此前的两类尝试均未选用：

- 把已分裂的子分支继续计入上游扇出，只会轻微增加任务数，未减少最大图。
- 对大根做固定时间会话切分，虽然可降低部分最大图规模，但会把根拆成大量片段，CADETS 宏观 F1 从 0.6843 降到 0.6385 或 0.5590。

后续如果重启该方向，应按子分支的进程谱系和行为相似度组成会话，而不是按固定分钟数切分；在没有这一证据前，保持默认切图。

## 采用与保留

采用同一时间切分下的 `2%` 正常验证分位阈值：它使 CADETS 覆盖全部 5 张已知恶意任务图，并使 TRACE 在不引入良性误报的情况下检出 2 张。CADETS 的宏观 F1 相比 1% 仅下降 0.0046，换来完整的恶意图召回；两数据集平均宏观 F1 从 0.5892 提升到 0.7551。

不采用 `5%`：TRACE 虽覆盖全部攻击任务，但 CADETS 良性误报由 8 增至 43。也不采用单纯扩大校准集：CADETS 有收益，但 TRACE 的阈值仍过高，不能成为跨数据集默认。

理论上，正常样本分位数是常见的一类无监督报警阈值选择方式；有限样本下应把目标误报率视为明确的部署操作点，而不是利用测试攻击标签追求最优值。参考：[Quantile Estimation for Detector Threshold Tuning](https://arxiv.org/abs/2105.12239)、[Cross Conformal Prediction for One-Class Classification](https://proceedings.mlr.press/v266/garg25a.html)。
